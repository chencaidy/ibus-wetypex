# 架构说明

## 目标

WeTypeX 将原版桌面输入核心接入 IBus，同时让 Linux 桌面负责输入上下文、进程隔离、音频、剪贴板和界面。设计目标是保留真实候选、账户和联网服务结果，并避免为了输入法启动完整 Wine 或虚拟机。

支持范围固定为 Linux x86-64 与原版 macOS 2.2.3.657。原版程序不是普通 Linux 动态库，因此设置过程会校验官方压缩包、提取核心与词典，并生成可由兼容宿主加载的映像和重定位清单。

## 运行组件

| 组件 | 职责 |
| --- | --- |
| `ibus-engine-wetypex` | IBus 输入法引擎、按键状态、候选、预编辑和提交 |
| `wetypex-engine-host` | 加载固定版本原版核心，提供所需 Darwin ABI |
| `wcwss_bridge.so` | 将原版网络调用桥接到 Linux curl/TLS/WebSocket |
| `wetypex-backend` | 在 Bubblewrap 中启动持久输入服务 |
| `wetypex-account` | 执行配对、设备组、同步、语音和传输业务请求 |
| `wetypex-clipboard` | 轮询设备组并交换剪贴板内容 |
| `wetypex-settings` | IBus 专用 GTK4 + libadwaita 设置窗口，管理输入、常用语和跨设备同步 |
| `wetypex-transfer` | GTK4 + libadwaita 隔空传送窗口，向关联设备发送文件和文件夹 |

## 输入路径

每个 IBus 都拥有独立会话、序号、epoch、候选修订号和本地模式状态。插件通过一行一个 JSON 对象的私有管道向后端发送按键。后端把输入交给原版会话，返回预编辑、候选和提交文本。

核心回调通过 eventfd 唤醒同一服务线程，由该线程生成异步状态快照并发送，保持输入操作和输出的串行顺序。快照携带会话、epoch、当前请求序号和单调更新号，提交文本只排出一次；旧序号、旧 epoch 和重复更新会被前端丢弃。前后端通过 `candidate_updates` 明确协商该能力：支持推送时无需轮询云候选；旧辅助核心仍使用原来的轮询，旧插件也不会收到无法处理的推送。

首次候选窗口等待正在处理的本地输入回复，回复到达便显示完整内容；超过约一帧则显示预编辑兜底。内嵌预编辑、语音和 V 工具不经过这段等待。等待由现有主计时器调度，采用毫秒级精度；取消、失焦和重置都会清除状态。

已显示的候选选择携带修订号，后端保留对应的候选 ID 快照，防止异步云候选更新改变选词结果。输入尚未返回候选时按空格或数字，选词请求会排在这些输入之后，由后端处理完字母再选择对应候选。空格遇到没有候选的组合时提交原始输入。

如遇到密码上下文 IBus 会直接结束后端；浏览器标记为敏感的普通输入仍可使用输入法。

## 原版兼容边界

兼容宿主只初始化原版 C/C++ 输入和业务区域，不运行 AppKit、Swift 设置窗口或官方桌面进程。宿主提供实际被使用的线程、文件、时间、区域设置、CoreFoundation 轻量对象和 libc++ ABI，并对未实现导入使用受控陷阱。

所有固定地址、结构尺寸和字段偏移都绑定于受支持的原版版本。设置工具同时校验压缩包和核心散列，避免用错误版本进入未定义行为。

## 网络与账户

账户身份由原版业务层生成并保存在 `account/identity.json`。六位匹配码、确认绑定、设备组和功能位都调用原版业务服务；项目不生成假账户，也不模拟成功结果。

输入后端仅在未开启单机模式且存在设备身份时联网。账户命令使用独立文件锁，防止多个原版业务上下文同时修改加密状态。

## 隔空传送

`wetypex-transfer` 可选择已关联设备发起传输，也可显示二维码邀请设备。连接建立后可发送文件或文件夹；传输核心根据设备和网络情况使用安全直连或中继。接收的文件保存在系统下载目录下的 `WeTypeX` 文件夹，临时传输数据位于用户数据目录。

## 同步

设备组返回的功能位映射如下：

- `0x1`：跨设备剪贴板。
- `0x2`：常用语同步。
- `0x4`：个人词库同步。

文字剪贴板使用原版文本消息；图片使用 `TypeImageOri` 和二进制字段。本地剪贴板由 GNOME Shell 扩展 `wetypex-clip-watcher@caidy.cc` 读取，`wetypex-clipboard` 通过 D-Bus 接收 `Changed` 后取回内容，并只在设备组剪贴板功能位 `0x1` 开启时上传；启用时以启动时的空选区建立本地基线，因此先于本机复制的远端内容也能收到。它是唯一的系统剪贴板写入与上传端，远端文字与图片分别通过扩展的 `SetText` / `SetImage` 写回，并像原版 Windows/macOS 客户端一样维护设备组内的单调版本游标。远端消息只有在版本更新、来源不是本机且尚未过期时才写入；本机上传成功后立即前移同一个版本游标，从而避免旧内容回传和多写入者竞态。

## 沙箱与文件权限

输入和账户宿主运行在 Bubblewrap 容器中，只读绑定系统库（包括宿主 `/lib64`）、证书与已准备运行时，可写目录限于对应状态目录。离线模式额外隔离网络命名空间。账户、AI、语音和剪贴板状态使用 `0700` 目录与 `0600` 文件。

WeTypeX 不把用户文本发送到自建服务器。启用云候选、同步、语音或 AI 时，相关内容会进入原版腾讯服务；单机模式关闭这些联网能力。
